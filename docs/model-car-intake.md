# Model-car intake

The one path for adding a car the owner bought (or pre-ordered) to the gallery at `/library/cars/`, from the owner's message or screenshot to the live card. The rules each step must meet live in [model-car criteria](model-car-criteria.md) and, for redraws, [model-car redraws](model-car-redraws.md); this page is the order of work.

## Where things live

| What                                                                                             | Where                                                              | Written by                                                                                                         |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| The car record: identity, scale, image fields, `blog_display_order`, visibility, purchase status | Life Records (`~/Projects/Life Records`)                           | Only the `life-records` MCP tools or `npm run lr -- <command>` in `~/Projects/MyRecordsApp`. Never edit its files. |
| The gallery data                                                                                 | `src/data/library/model-cars.json`                                 | `lr export blog`, copied in; then `npm run library:car-variants` adds `displayImageVariants`                       |
| Display images and variants                                                                      | R2, served from `https://cdn.theneverless.com/library/model-cars/` | `npm run library:car-image` and `npm run library:car-variants`                                                     |
| Evidence: screenshot, official-source check, references, prompts, outputs, captures, receipts    | `../drafts/<topic>-YYYY-MM-DD/` (private)                          | The session doing the intake                                                                                       |

Purchase and fulfillment status stays in Life Records. Life Records exports only `blog-ok` cars and strips private fields, so `model-cars.json` never carries them.

## Steps

1. **Start clean.** Run `npm run lr -- export blog --out "$TMPDIR/lr-blog-export"` in `~/Projects/MyRecordsApp` and read its report. It should show no unexplained differences and an order that matches the blog. Fix an existing mismatch in Life Records first, so the new car is the only change.
2. **Identify the car.** Treat the screenshot as evidence of which car, never as the card image. Establish manufacturer, SKU, scale, color, livery/number, edition and accessories. Do not ask whether it has arrived or how it was bought: a car the owner brings is theirs. Ask only about an identity conflict the official source cannot settle. Save the screenshot in a new drafts folder.
3. **Record it in Life Records.** Process the inbox, search for an existing thing, then add it or update it: kind `model_car`, the identity fields, and status `owned` (`ordered`/`deposit` only when the owner calls it a pre-order). Dates only as the owner states them; keep purchase evidence such as a listing URL and price under the private `details.purchase`. Set `sources[0].ref` to the SKU-style blog id (the export uses it as the card id). A car the owner brings to the blog session goes on the gallery, so set `visibility` to `blog-ok` and set `details.blog_display_order` to place it within its scale group (1:18, 1:64, 1:43, 1:32).
4. **Check the official source.** Open the manufacturer's product page and full gallery, inspect the actual photographs, and save the check (page URL, image URLs, views inspected, the chosen reference and why) in the drafts folder. Fall back to a distributor or retailer only with a written reason. The check must be complete before step 5.
5. **Make the card image.**
   - **1:64:** studio redraw by default. Claude Code has no allowed image model, so it writes the reference, per-model prompt and invariants into the drafts folder and gives the owner a short brief to run in Codex (OpenAI `image_gen`, the only accepted model). Codex saves its output in the same folder. Set the prompt's framing from the same scale group's existing cards: measure how much of the width their cars fill (1:43 redraws fill about 94%, 1:64 redraws 61 to 90%). Inspect the output against the reference and those neighbors; send corrections back to Codex rather than accepting a near miss. A framing-only miss may instead be fixed with a 3:2 crop of the output that clips nothing, recorded in `imageCrop`.
   - **Other scales:** a conservative 3:2 crop of the chosen original photograph, unless the owner asked for a redraw of that car.
6. **Upload the image.** `npm run library:car-image -- --id <id> --file <absolute path to final image> --receipt <absolute drafts folder path>/upload-receipt.json` (add `--label ai-redraw` for a redraw). It uploads to a content-hashed key, never overwrites, and verifies the CDN bytes.
7. **Put the image fields in Life Records.** `npm run lr -- update <thing id>` with the `displayImage` URL from the receipt, the source fields (`officialUrl`, `displaySourceImage`, `displaySourceUrl`, `imageSourceType`, `imagePresentation`, `imageSourceStatus`, `imageCrop`, dimensions, generation provenance for a redraw). Field meanings follow the accepted rows in `model-cars.json`.
8. **Export into the blog.** Run the export again. The report should show only the new car as added (and nothing unexplained). Copy its `model-cars.json` into `src/data/library/`. The owner's request to add the car is the go-ahead for this copy; it does not authorize publishing.
9. **Make the variants.** `npm run library:car-variants -- --only <id>`, then `npm run library:car-variants -- --verify`.
10. **Review.** Run `npm run ship -- --preflight --only src/data/library/model-cars.json`, then `--review` with the same flags; it serves exactly the build that would ship. Inspect `/library/cars/` there yourself first: the new card at desktop and phone sizes, Chinese and English, light and dark, with its neighbors. Then give the owner that link, with the drafts folder available but not required reading.
11. **Publish on "push".** Run the printed `npm run ship -- --yes --digest <d>` with the same flags. It records the preview approval, runs the release checklist, commits only `model-cars.json`, pushes and watches the deploy. Then check the live card and image URLs.
12. **Close out.** Rerun the export: it should match the blog exactly, which also proves the variants carried through. Update `../drafts/current-work.md`.

Batch scripts in older drafts folders (`prepare.py`, `upload-assets.mjs` and similar) edited Life Records files directly or hardcoded old paths. Do not copy them; use the commands above.
